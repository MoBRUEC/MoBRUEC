# AGENTS.md — mohammed-brueckner.com Website

Guidance for AI agents working on this repo. Read this before changing anything.

## What This Repo Is

Jekyll site (`jekyll-theme-architect`) on GitHub Pages, served at https://mohammed-brueckner.com. Push to `master` = automatic live deploy in ~1 minute. There is no staging; a broken build leaves the last good build serving (site can go stale, never dark).

## Access & Deploy Loop (established 2026-08-15)

- All agent git operations use a **fine-grained PAT** (`MOBRUEC_SITE_PAT`, stored as a Codespaces secret on `MoBRUEC/platformeconomies`, value write-only). Scope: this repo only — Contents RW, Pages RW, Pull requests RW. 90-day expiry.
- The broad codespace `GITHUB_TOKEN` must NOT be used for this repo.
- The remote URL is token-free. PAT resolution order: (1) `$MOBRUEC_SITE_PAT` env var — injected into every NEW codespace from the Codespaces secret, use it as-is; (2) ONLY in codespaces that predate the secret: `~/.mobr_site_pat` (chmod 600, transient — delete it when the session's work ends, never recreate it if the env var exists). Usage without printing: `MOBRUEC_SITE_PAT=${MOBRUEC_SITE_PAT:-$(cat ~/.mobr_site_pat)}; git push "https://x-access-token:${MOBRUEC_SITE_PAT}@github.com/MoBRUEC/MoBRUEC.git" <branch>`. NEVER write the literal token into commands, chat output, files inside a repo, or logs.
- Deploy verification loop after every push: poll `gh api repos/MoBRUEC/MoBRUEC/pages/builds/latest` until `built` for the pushed commit SHA (check the SHA — "built" alone may be the previous build), then `curl` the changed pages and assert HTTP 200 + content markers. Rollback: `git revert` + push, never force-push.

## Book Promotion Policy (revised 2026-09-12)

The site promotes the owner's books, currently **Platform Economies** (published 1 September 2026; paperback ASIN B0H3VVNPZ3, Kindle ASIN B0GXN4PRB5, ISBN 979-8-1954-5157-8; book page `/platform-economies/`; external site https://platformeconomies.com, whose `/buy` route sends each visitor to their own Amazon marketplace).

**The old "BY THE WAY:" block near the top of high-traffic pages is retired.** On the PlantUML hub it opened with a 180-word pitch and a five-country Amazon strip before the first line of PlantUML, followed by a second callout for two more titles and three further interruptions — six placements and 14 Amazon links on the page that carries 79% of the site's clicks, whose readers arrive to solve a diagramming problem. Cut on 2026-09-12 after independent SEO and brand review.

The policy for the hub and for every new page:

1. **Above the fold:** at most one plain sentence with one link, in the page's own voice. No label, no box, no button, no flag emoji, no locale list.
2. **Mid-page:** the argued callout, placed after the reader has what they came for — on the hub, after "A Real-World Enterprise Case". The transition is earned by argument, not by placement.
3. **End of page:** an author block. Other titles get one mention there and nowhere else on the page.
4. **Never** a locale strip on a content page. Buyers go to `https://platformeconomies.com`.
5. **No book promotion at all** on narrow technical reference pages such as `plantuml-how-to/skinparam/`.

Pages still carrying the retired block (checked 2026-09-13): `apiops/`, `archimate/`, `changemanagement/`, `claude-certified-architect/`, `curation/`, `databricks/`, `databricks/cost-calculator/`, `how-to-ai/`, `integration/`, `jArchi-Build/`, `mlopswithdatabricks/`, `plantuml-how-to/c4-diagrams/`, `plantuml-how-to/plantuml-vs-mermaid/`, `plantuml-how-to/templates/`, `plantuml-how-to/troubleshooting/`, `platform-economy/`, `podcast/`, `won-contests-mohammed-brueckner/`. `developer-platforms/index.html` has an amber banner variant in its own design system. **Do not add new ones; convert a page to this policy when it is next touched.**

## Writing Style (keep it true)

Direct practitioner voice, first person. Bold key terms. Short punchy sentences mixed with longer ones. Dry parenthetical humor occasionally. `---` separators. Blockquotes for promos. Sparing emoji as section markers (📚 💡 🎧). No hype, no consultant-speak, no "In today's fast-paced world". Concrete numbers over adjectives. Match `plantuml-how-to/`, `archimate/`, `how-to-ai/` for reference tone.

## Conventions

- Folder-per-page: `<topic>/readme.md` (or `index.html` for standalone pages like developer-platforms, double-trinity-change-model). Sub-pages as nested folders (`plantuml-how-to/templates/readme.md`).
- Internal links between cluster pages are relative (`../troubleshooting/`); links from other sections are absolute (`https://mohammed-brueckner.com/plantuml-how-to/`).
- **Diagrams on pages:** use ```` ```mermaid ```` fences for rendered visual diagrams (mermaid.js is **loaded on demand** by `_layouts/default.html`, only when a page contains a `.language-mermaid` block — the 2.9 MB library used to be render-blocking on every page, so **never re-add a static mermaid `<script>` to the layout**; a diagram needs no layout change; see jArchi-Build for the pattern). Keep PlantUML in ```` ```plantuml ```` fences only where the code itself is the deliverable (copy-paste templates/examples). After adding mermaid, Playwright-verify the SVG actually renders (`.language-mermaid svg` present, zero console errors) — mermaid fails client-side and silently.
- **Standalone HTML pages inherit NOTHING from the Jekyll layout** (no nav, no seo-tag, no favicon, no noopener injection). Every standalone page (`developer-platforms/`, `scorecard/`, `double-trinity-change-model/`, `databricks/*.html`, `aicommunity/`, formatters) must carry its own: canonical pointing at ITSELF (two pages once canonicalized themselves away to /publications and / — instant de-indexing), og:image, favicon, a visible link back to the homepage, a path to the book funnel, and rel="noopener" on target="_blank" links. Never use `<base target="_blank">` — it breaks in-page anchors (opens TOC links in new tabs).
- **Dead-link check must cover three rot forms:** external targets that vanished, trailing spaces inside href (`/publications%20` = 404), and links to `readme.md` files (serve raw markdown, not a rendered page — always link the folder URL).
- **Never invent metadata.** No episode guests, dates, or attributions that cannot be verified (podcast cards scrubbed 2026-08-15). If it cannot be checked, it does not ship.
- **Full-estate scrub after every big content round:** run an audit agent over EVERY public page (folder pages + standalone HTML) for cross-linking (no stranded pages), canonical/og/H1/lang, dead links, and polish. Page-by-page checks miss estate-level patterns (2026-08-15 scrub: 20+ findings after individual QA had passed).
- After ANY content change: run a repo-wide dead-link check (relative + absolute internal links) before pushing. A dead-link checker trap: `learning`, `excel` etc. also match plain words — check for actual link syntax only.
- **Front matter + folder-per-page trap (hit 2026-08-15):** adding YAML front matter to a `readme.md` makes Jekyll serve it at `/readme.html` instead of as the folder index — every folder page 404s. Any readme with front matter MUST also set `permalink: /<folder-path>/` in that front matter. Root `README.md` is exempt (no front matter there).
- **Live-render validation is mandatory for layout/nav/HTML changes:** after Pages reports `built` for the pushed SHA, run Playwright (bundled in the platformeconomies codespace: `NODE_PATH=/workspaces/platformeconomies/node_modules node test.js`, browsers at `~/.cache/ms-playwright`) against the live URLs with `pageerror`/`console` listeners, assert HTTP 200 + zero JS errors + content markers, click key nav links (assert the landed page is not a 404 — check a content marker, not just the URL), and view a screenshot. Note: Pages needs ~30–60s after "built" for new files to stop 404ing; also a URL-based nav check alone cannot distinguish a 404 page.
- **jekyll-seo-tag owns `<title>` and `<link rel="canonical">`.** The layout must NOT hardcode its own (removed 2026-08-15 after every page emitted two of each). Titles/descriptions live in page front matter; the site-wide fallback is `_config.yml` `title`/`description`.
- **og:image:** site-wide default via `defaults:` in `_config.yml` (book cover). Page-level `image:` front matter overrides, and MUST be an absolute path (`/platform-economies/...`) — relative paths resolve against the site root and 404 (bug hit 2026-08-15).
- **platformeconomics.com is a single-page site.** Do NOT link to sub-routes (gamebook25*, /podcast, /episodes/*) — they 404 (dead links removed 2026-08-15). Podcast links go to the Spotify show URL or `/podcast/`.
- PlantUML code blocks in new pages must **render** cleanly before shipping: download the jar (`https://github.com/plantuml/plantuml/releases/latest/download/plantuml.jar`), render each block with `java -jar plantuml.jar -tpng` into a scratch dir (install Graphviz rather than falling back to `!pragma layout smetana`: Smetana silently ignores `skinparam linetype ortho`/`polyline`, so a diagram can render without errors and still look wrong — **view the PNG**; verified 2026-09-12 against PlantUML 1.2026.8 and Graphviz 2.43.0) and assert no "contains errors" on stderr. `java -jar plantuml.jar -syntax` is NOT sufficient — stdlib macros and relationship suffixes (e.g. `Strategy_Capability`, `Rel_Flow_Right`) only resolve at render time; wrong ones pass `-syntax` silently (trap hit and fixed 2026-08-15).
- **Retired URLs redirect** from the *destination* page's front matter as `redirect_from:` (jekyll-redirect-from). Live since 2026-09-12: `/microsoft-fabric/` → `/databricks/`; `/excel/` and `/excel/excel-magic.html` → `/how-to-ai/`; `/AMaaS/` → `/platform-economy/`. GitHub Pages cannot serve a real 301 — the plugin emits a meta-refresh stub with a canonical. Only redirect where the topic genuinely continues; an unrelated target is a soft 404 and worse than a 404.
- **hreflang** is declared per page as an `alternates:` list in front matter and emitted by the layout. The set must be reciprocal and self-referential, plus `x-default`, or Google ignores it. Live on `plantuml-how-to/` (en) and `plantuml-anleitung/` (de).
- **Author name:** the canonical form is **Mohammed Brückner**, with the umlaut — `_config.yml` `title`, visible text, schema `name`. "Mohammed Brueckner" and "M. Brückner" are `alternateName` only. The layout's Person node has `@id` `https://mohammed-brueckner.com/#person`, which platformeconomies.com references, so both domains resolve to one entity. Domain and paths stay ASCII.
- **Structured data on cluster pages:** `plantuml-how-to/readme.md` carries TechArticle + BreadcrumbList JSON-LD as raw `<script type="application/ld+json">` blocks after the front matter (same pattern as `platform-economies/readme.md`). New cluster pages follow `plantuml-how-to/skinparam/readme.md`.
- **IndexNow:** key file `/94401e4d4f0f3f5076d3290bb508b2e4.txt` at the site root — public by design, never delete it. After a content change, POST the changed URLs to `https://api.indexnow.org/IndexNow` with JSON `{"host":"mohammed-brueckner.com","key":"94401e4d4f0f3f5076d3290bb508b2e4","keyLocation":"https://mohammed-brueckner.com/94401e4d4f0f3f5076d3290bb508b2e4.txt","urlList":[...]}`. HTTP 200 or 202 is success (202 on first use). Reaches Bing, Yandex, Seznam and Naver without an account.
- **Keep `/apiops/` stable.** The Operating Engine button on platformeconomies.com links to `https://mohammed-brueckner.com/apiops/`.
